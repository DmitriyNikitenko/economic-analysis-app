# Классификация объектов OpenStreetMap

## 1. Принципы классификации

* Классификация выполняется по тегам объекта, а не по его названию.
* Правила хранятся в конфигурационном файле `rules.yaml`, чтобы их можно было изменять без изменения кода.
* Для каждого объекта определяется основной тип субъекта, домены экономической активности и аналитические роли.
* Если объект подходит под несколько правил, основная категория выбирается по приоритету. Все совпавшие правила сохраняются для проверки.
* Если ни одно правило не подошло, объект получает тип `unclassified`.
* Исходные свойства и геометрия объекта сохраняются.

## 2. Какие теги используются

### 2.1. Финансовые организации

| Объект | Условие | Интерпретация |
| :--- | :--- | :--- |
| Банк | `amenity=bank` | Отделение или объект банковского обслуживания |
| Банкомат | `amenity=atm` | Отдельный объект банкомата |
| Финансовый офис | `office=financial` | Офис финансовой организации |
| Небанковские финансовые услуги | `shop=money_lender` | Организация, предоставляющая услуги кредитования |

Основной домен - `money`. В текущей модели эти объекты относятся к роли `supply`, поскольку представляют места предоставления финансовых услуг.

### 2.2. Населённые пункты

Используются значения тега `place`:
* `city` - город;
* `town` - небольшой город или крупный населённый пункт;
* `village` - село или деревня;
* `hamlet` - небольшой населённый пункт;
* `isolated_dwelling` - отдельное жилище или изолированная застройка.

В текущей конфигурации для них заданы:
* домен `money`, роль `demand`;
* домен `labor`, роль `supply`.

### 2.3. Работодатели и офисы

Единого универсального тега работодателя в OSM нет. Поэтому для первоначального поиска используются несколько групп тегов.

| Тег или значение | Интерпретация |
| :--- | :--- |
| `office=company` | Офис компании |
| `office=government` | Государственная администрация |
| `office=employment_agency` | Агентство по трудоустройству |
| `office=insurance` | Страховая организация |
| `office=it` | IT-компания |
| `office=telecommunication` | Телекоммуникационная компания |
| `office=energy_supplier` | Поставщик энергии |
| `office=architect`, `accountant`, `lawyer`, `notary`, `estate_agent` | Профессиональные услуги |
| `office=ngo`, `association`, `charity`, `foundation`, `religion` | Некоммерческие и общественные организации |
| `office=yes` | Офис без уточнения специализации |

В текущей конфигурации эти объекты относятся к типу `employer`, домену `labor` и роли `demand`.

### 2.4. Промышленные объекты и территории

| Тег | Интерпретация |
| :--- | :--- |
| `landuse=industrial` | Промышленная территория |
| `man_made=works` | Производственный объект |
| `industrial=*` | Указание на промышленную деятельность или её тип |

### 2.5. Магазины и услуги

| Тег | Интерпретация |
| :--- | :--- |
| `shop=*` | Магазин или торговый объект |
| `amenity=*` | Объект определённого вида услуг или инфраструктуры |

Магазины и объекты услуг относятся к домену `goods_services` и роли `supply`.

## 3. Тип, домен и роль

* **Тип субъекта (`type`)**  
  Описывает категорию объекта: например, `bank`, `atm`, `settlement`, `employer`, `shop` или `industrial_area`.

* **Домен (`domains`)**  
  Указывает область экономического анализа:
  * `money` - финансовые услуги;
  * `labor` - рынок труда;
  * `goods_services` - товары и услуги.  
  Один объект может относиться к нескольким доменам.

* **Роль (`roles`)**  
  Описывает предполагаемую функцию объекта в аналитической модели:
  * `supply` - объект предложения;
  * `proxy` - объект спроса;

---

## 4. Приоритеты правил

Каждое правило в `rules.yaml` содержит:
* `id` - уникальный идентификатор правила;
* `priority` - приоритет при выборе основной категории;
* `match` - условия по тегам;
* `type` - основной тип субъекта;
* `domains` - список доменов;
* `roles` - роли по каждому домену.

Если объект подходит под несколько правил, основная категория определяется правилом с максимальным приоритетом. Идентификаторы всех совпавших правил сохраняются в `matched_rules`.

Если ни одно правило не совпало, объект получает `type=unclassified`, пустой список доменов и пустой набор ролей.

---

## 5. Структура результата

Классификация записывается в свойство `classification` объекта JSON.

Пример:
```json
{
  "classification": {
    "type": "bank",
    "domains": ["money"],
    "roles": {
      "money": "supply"
    },
    "matched_rules": ["bank"]
  }
}
